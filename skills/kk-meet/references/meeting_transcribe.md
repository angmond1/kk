# 회의 기록으로 회의내용 쓰기 — 글 · 녹음 (2026-09-27 사용자 지시)

회의내용은 **실제 회의 기록**에서 가져오는 것이 가장 정확하다. 그래서 회의 주제를 묻기 전에 먼저 기록을 달라고 한다.
**사용자가 고민하거나 주의를 쓰지 않게 한다**(사용자 지시): 선택지를 늘어놓지 않고, 녹음은 휴대폰 녹음 앱이나 클로바노트 같은 전용 프로그램으로
글로 바꿔서 달라고 유도한다 — 사용자 대부분은 PC 사양이 넉넉하지 않거나 그래픽카드가 없다. 이 PC 에서 음성 인식을 설치하는 방법은
녹음 파일을 그대로 주거나 휴대폰·클로바노트가 어렵다고 할 때만, 한 줄로 짧게 제안한다.

## 1. 순서 (건마다 — 같은 날 식당+카페는 한 건. 여러 건이면 번호를 붙여 한 번에)

| 순서 | Claude 가 하는 말 | 다음 |
|---|---|---|
| ① 기록 요청 | "이 회의 내용을 적어 둔 글이 있으면 주세요(회의 메모·녹취록·회의 자료). 녹음만 있으면 휴대폰 녹음 앱의 텍스트 변환이나 클로바노트(https://clovanote.naver.com)로 글로 바꿔서 주시면 됩니다. 클로바노트는 녹음이 외부 서버에 올라가니 내부 회의는 보안 기준을 확인해 주세요." | 글을 받으면 2절대로 읽고 5절대로 초안 |
| ② 녹음 파일을 그대로 줄 때 | (휴대폰·클로바노트가 어렵다고 하거나 녹음 파일만 보냈을 때만) `transcribe.py check` 를 조용히 돌리고 `[사용자 안내]` 한 줄만 전한다 | 3절 |
| ③ 기록 없음 | "9/1 ○○식당 건의 회의 주제를 알려주세요." → "회의 내용을 적어 주시면 그대로 기록하겠습니다." → 적어 주지 않으면 "그럼 제가 이 과제의 제안서·보고서를 보고 주제에 맞게 회의내용을 채울 수 있습니다. 그렇게 할까요?" | 확인받은 뒤에만 제안서 근거 초안(SKILL 단계 5 ③) |

- 사용자가 준 글이 이미 회의록 형태면(제목·내용이 정리돼 있으면) 그대로 쓰고 **고치지 않는다**. 메모·녹취록처럼 정리가 필요할 때만 초안을 만든다.
- 휴대폰 녹음 앱: 갤럭시 기본 음성 녹음 앱 등 최신 휴대폰 녹음 앱에는 녹음을 글로 바꾸는 기능이 있다(기종·버전에 따라 없을 수 있다). 사용자가 방법을 물으면 그 앱의 녹음 파일 메뉴에서 텍스트 변환을 찾아 보라고 짧게 안내한다.
- 클로바노트: 네이버 계정으로 웹·앱에서 녹음 파일을 올리면 말한 사람별로 글로 바꿔 준다. 결과를 텍스트로 내려받아 주면 된다.
- 온라인 회의(Teams·Zoom 등)는 회의 도구가 만든 녹취록·자막 파일(docx·vtt)을 그대로 주면 된다.

## 2. 글로 된 기록 읽기

| 형식 | 방법 |
|---|---|
| txt · md · 채팅에 붙여 넣은 글 | 그대로 읽는다 |
| pdf | Read 로 바로 읽는다(스캔 이미지 pdf 도 읽힘) |
| docx(워드, Teams 녹취록) · hwpx(한글) · vtt · srt(자막) | `python scripts/transcribe.py text <파일>` → `{kiki_root}\meeting\transcripts\<이름>_회의기록.txt` 를 읽는다(자막 시각표·서식을 빼 글자 수가 줄어든다). 마지막 줄 `[요약] 글 N자` |
| hwp(구형 한글) | 바로 못 읽는다 → "한글에서 hwpx 나 pdf 로 저장해 주세요" |
| 사진(화이트보드·손글씨 메모) | Read 로 이미지를 읽는다. 글씨가 불확실한 부분은 표시해 확인받는다 |

## 3. 녹음 파일을 그대로 받았을 때 — 이 PC 에서 바꾸기
1. `python scripts/transcribe.py check <녹음 파일>` 을 **조용히** 돌린다(몇 초, 설치 없이 PC 사양·설치 상태·녹음 길이·녹음 시작 시각을 읽는다). 출력:
   - `[이 PC]` `[설치]` `[녹음]` — 사실(Claude 용).
   - `[Claude]` — 실행·설치 명령, 모델(Claude 만 쓴다, 사용자에게 말하지 않는다).
   - `[사용자 안내]` — **이 한 줄만 그대로 전한다.** 설치 명령·모델 이름·용량 계산·그래픽카드 라이브러리 같은 세부는 말하지 않는다(사용자가 물으면 답한다).
   - `[요약] 설치됨 예/아니오 | 이 PC 변환 그래픽카드/CPU/어려움 | 예상 … | 첫 내려받기 NGB | 녹음 N분`.
2. `[사용자 안내]` 는 다섯 가지 중 하나다.

| 이 PC | 사용자 안내(요지) | Claude 가 이어서 |
|---|---|---|
| 이미 설치됨·그래픽카드 | "설치된 음성 인식으로 바로 글로 바꾸겠습니다(그래픽카드, 몇 분)." | 묻지 않고 바로 run |
| 이미 설치됨·CPU | "…바로 바꾸겠습니다. 그래픽카드가 없어 시간이 걸리니 그동안 다른 일을 하셔도 됩니다." | 묻지 않고 바로 run(백그라운드) |
| 미설치·그래픽카드 | "설치하면 직접 바꿀 수 있습니다. 그래픽카드가 있어 빠르지만 처음 한 번 약 NGB 를 내려받습니다. 설치할까요?" | 동의하면 `[Claude]` 의 설치 명령 → run. 아니면 휴대폰·클로바노트 한 줄 |
| 미설치·CPU | "설치하면 직접 바꿀 수는 있지만, 그래픽카드가 없어 오래 걸립니다(…). 처음 한 번 약 NGB 도 내려받습니다. 설치할까요?" | 같음 |
| 쓸 수 없음 | "이 PC 에서는 음성 인식 프로그램을 쓰기 어렵습니다. 휴대폰 녹음 앱이나 클로바노트로 글로 바꿔 주세요." | ① 로 |

3. **변환** — `[Claude]` 줄대로 `python scripts/transcribe.py run <녹음 파일> --model <모델> --hint "<과제명> <전문 용어> <참석자 이름>"` 를 **백그라운드로** 돌린다(긴 회의는 수십 분 — 셸 제한 시간에 걸리지 않게). 사용자에게는 "변환 중입니다, 끝나면 알려 드립니다" 한 줄. 30초마다 `진행 N% …` 줄이 찍힌다(Claude 용).
   - `--hint` 는 과제명·장비명·물질명·참석자 이름을 띄어쓰기로 — 인식기가 그 단어를 더 잘 알아듣는다.
   - 그래픽카드가 안 되면 run 이 스스로 CPU 로 바꿔 계속한다. 원본 녹음은 옮기거나 지우지 않는다. 결과는 `{kiki_root}\meeting\transcripts\<녹음 이름>_녹취록.txt`(`[분:초] 문장`, 덮어쓰지 않음).
4. **결과 점검**(Claude 용) — 마지막 줄 `[요약] 녹음 N분 → 글 N자(말한 구간 N분, N문장, 지어낸 문구 N개 뺌), 모델·장치, N분 걸림 → <파일>`.
   - `⚠ 말한 분량에 비해 글이 너무 적습니다` → 한국어 회의가 맞는지·녹음 소리가 작은지 확인하고, `--model turbo` 로 한 번 더 또는 휴대폰·클로바노트.
   - `⚠ 그래픽카드 준비 실패 … CPU 로 다시` 는 자동 복구된 것.
   - `ERR 모델 … 내려받지 못했습니다` → 인터넷·사내망 프록시·VPN 확인 후 1회, 안 되면 휴대폰·클로바노트.
   - `ERR faster-whisper 가 없습니다`(종료 코드 2) → 설치 동의부터.
5. 녹취록을 읽고 5절대로 초안.

## 4. 판정 기준과 실측 (Claude 용 — 사용자에게 설명하지 않는다)
- 그래픽카드: NVIDIA, 메모리 4GB 이상 → 정확한 모델 turbo. 처음 내려받기 = 프로그램 약 0.1GB + 모델 1.6GB + 그래픽카드 라이브러리 약 1.4GB(설치 후 약 2GB).
- CPU: 물리 8코어·메모리 8GB 이상이면 정확한 모델 turbo, 아니면(또는 turbo 예상 상한이 40분을 넘으면) 가벼운 모델 small(약 0.5GB). 메모리 6GB 미만·물리 2코어 이하는 "오래 걸림" 이 크다 — 그래도 사용자가 원하면 한다.
- 쓸 수 없음: 파이썬 3.9 미만·64비트 아님·여유 공간 부족.
- 예상 시간은 아래 실측을 기준으로 코어 수를 반영하고 PC 세대 차이를 감안해 0.8~2.5배로 넓게 잡은 추정이다. 녹음 길이를 못 읽으면 한 시간으로 가정한다.

| 실측 2026-09-27, 한국어 합성 회의 음성 3~10분 | 모델 | 한 시간 녹음 환산 | 글자 오류율 |
|---|---|---|---|
| RTX 5080 그래픽카드 | turbo | 약 2분 | 7~8% |
| 12코어 데스크톱 CPU | turbo | 약 14분 | 7% |
| 12코어 데스크톱 CPU | small | 약 9분 | 7~8% |

글자 오류는 대부분 숫자 표기 차이(칠십 퍼센트 → 70%)였고, 실제 오인식은 발음대로 적은 전문 용어(촉매 → 총매) 정도였다. 합성 음성은 깨끗하므로 실제 회의는 오류가 더 많다.

## 5. 기록(글·녹취록) → 회의 제목·회의내용 초안
- **기록에 있는 내용만** 쓴다 — 기록에 없는 성과·수치·결정을 지어내지 않는다. 자동 변환 녹취록은 사람 이름·과제명·용어가 틀릴 수 있으니, 확실하지 않은 말은 초안에서 표시해 확인받는다.
- **회의 제목** = 주된 안건 한 줄. 과거 회의 제목과 같거나 비슷하면(중복 방지 스캔, SKILL "중복 방지") 알리고 다른 표현을 제안한다.
- **회의내용**(10만원 이상) = 논의 사항·결정 사항·후속 조치를 `1.` `2.` 항목으로, 항목 사이 빈 줄, 항목당 하위 불릿 4개 정도, **괄호 금지**(`meeting_form.md` 회의내용 절). 10만원 미만은 목적 한 줄.
- 초안을 **보여 주고 승인받은 뒤** 회의록 팝업에 입력한다(사용자가 고치라는 곳만 고친다).
- 참석자는 녹취록에서 추정하지 않는다 — 목소리로 사람을 구분하는 기능은 무겁고 부정확하고, 내부·외부 참석자는 참여연구원 여부로 서버가 판정한다. 명단은 SKILL 단계 7 대로 묻는다(클로바노트의 화자 이름은 참고만).

## 6. 회의시간 힌트 (SKILL 단계 8)
check 의 `[녹음]` 줄: `녹음 시작 YYYY-MM-DD HH:MM(파일 정보)` 또는 `파일 이름 시각 …` + 길이. 녹음 시작 시각과 길이로 회의시간을 제안한다(예: 13:02 시작·62분 → 13:00~14:05). 카드 승인 시각으로 짐작하는 것보다 우선하되 사용자 확인. `파일 수정` 시각은 복사할 때 바뀔 수 있어 참고만.
휴대폰·클로바노트로 바꾼 글만 받았으면 녹음 시각을 모르니 종전대로 카드 승인 시각으로 제안한다.

## 7. 보관·보안
- 녹취록·회의기록 텍스트는 `{kiki_root}\meeting\transcripts\` 에만 둔다(로컬). repo·외부 서비스·메일로 보내지 않는다. 회의록 엑셀에는 요약만 남는다.
- 모델 파일은 `{kiki_root}\_models\whisper\`(지워도 다음 변환 때 다시 받는다). 프로그램을 지우려면 `python -m pip uninstall faster-whisper`.
- 원본 녹음 파일은 사용자 것 — 옮기거나 지우지 않는다.
