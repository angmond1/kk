# kk-dooray — KIST Dooray 업무·드라이브

## 핵심 한 줄
**1 찾기**(업무+드라이브를 한 번에, 서버 검색) · **2 자세히**(본문·댓글·첨부·폴더 경로) · **3 파일 내용 읽기**(허락 후, 브라우저 메모리에서만) · **4 내려받기**(업무 첨부·드라이브 → PC, 허락 후) · **5 쓰기·올리기**(업무 글·댓글·첨부, 드라이브 — 미리보기 → 사용자 확인 → 실행).

## 왜 빠른가
- Dooray 검색창이 쓰는 **서버 검색을 그대로** 부른다 — 프로젝트·폴더를 하나씩 열어 보지 않는다. 업무 약 0.5초, 드라이브 약 3초.
- **한 번 호출(`find`)** 에 동의어 묶음 여러 개 동시 검색 → 합치기 → 위쪽 업무의 본문·첨부·댓글과 드라이브 파일의 폴더 경로까지 읽는다(실사용 2~5초).
- **구조를 내재화**했다 — 웹 주소의 번호가 곧 API id(프로젝트·업무·폴더·파일·첨부), 드라이브 id 는 프로젝트 정보에, 파일은 파일 호스트로 307 → 찾은 링크를 그대로 받기·쓰기 명령에 넘겨 **탐색 없이 한 명령**(1~3초). 주소·본문 형식은 `references/wapi_search.md`(찾기)·`references/api_io.md`(쓰기·받기).
- 결과를 탭에 들고 있으므로 "그중 hwp 만", "○○ 가 올린 것만" 같은 **후속 질문은 다시 검색하지 않고** `only()` 로 거른다.

## 검색 범위 (2026-09-29 실측 — 검색어를 고를 때 반영)
| | 업무 | 드라이브 |
|---|---|---|
| 찾는 곳 | 내가 속한 프로젝트 전체 업무의 **제목·본문·댓글** | 내가 볼 수 있는 모든 드라이브의 **파일·폴더 이름 + 올린·고친 사람 이름** |
| 파일 속 글 | 첨부 파일 속은 검색 안 됨 | **파일 속 글은 색인 안 됨** (슬라이드 안 낱말로는 0건) |
| 한 묶음 안 여러 낱말 | AND (순서 무관) | AND |
| 걸리는 시간 | 약 0.5초 | 약 3초 |

→ 드라이브는 **파일 이름에 들어갈 말**(날짜 `yymmdd`·발표자·과제 약칭·"발표"·"결과정리")과 **올린 사람 이름**으로 찾는다. 물질명 같은 내용 낱말은 업무에서 찾고, 파일 속은 기능 3 으로 확인한다.

## 전제 (환경)
- **찾기·읽기(기능 1~3)**: 평소 쓰는 Chrome(Claude in Chrome 확장) + Dooray 로그인(`kist.gov-dooray.com`) + KIST 사내망(밖이면 VPN). 토큰·Python·설정 파일 불필요, 새 창(chrome-devtools)도 불필요. 환경 점검은 [`../_shared/environment_setup.md`](../_shared/environment_setup.md) 0단계.
- **받기·쓰기·올리기(기능 4~5)**: Python 3 + `requests` + **Dooray 개인 토큰** `<kiki_root>/token.txt`(kk-pay·kk-wiki 와 같은 파일) — 업로드는 세션 쿠키로 되지 않는다(kk-pay 실측). 토큰이 없으면 필요한 순간에만 안내: 발급 https://kist.gov-dooray.com/setting/api/token → `token.txt` 의 `Dooray token:` **다음 줄**에 붙여넣고 저장(절대경로를 보여 준다). ⚠️ **채팅창에 토큰을 붙여넣지 말라고 항상 경고**. 토큰이 없어도 받기는 브라우저로 한 파일씩 된다(기능 4 끝).

## 실행 준비 (매 작업 시작 시)
1. `tabs_context_mcp` → `kist.gov-dooray.com` 탭이 있으면 그 탭(어느 화면이든 된다), 없으면 `navigate` `https://kist.gov-dooray.com/task/to`. 로그인 화면이 뜨면 "Dooray 에 로그인해 주세요" 안내 후 중단.
2. **코어 주입**: `scripts/kk_dooray_ops.min.js` 를 Read → `javascript_tool` 로 inject → 반환 `kk-dooray-ops/1.1 =^.^=` 이면 성공. 원본 `kk_dooray_ops.js` 는 읽을 필요 없다(주석만 다름). 탭을 새로고침하면 다시 주입.
3. **2-스텝**: 비동기 호출은 결과를 window 에 두고 마지막 식은 문자열로 — `window.__d=null; kkDooray.find(…).then(r=>window.__d=r, e=>window.__d={error:String(e)}); 'started'` → 다음 호출에서 `kkDooray.fmtFind(window.__d)`. 아직이면 `(아직 — …)` 이 오니 2~3초 뒤 다시. 오류 처리(`e=>…`)를 빼면 로그인 만료가 영원히 '아직'으로 남는다.
4. **출력 제약**: 반환 문자열은 ~1,000자에서 잘린다 → `fmt*` 포매터가 글자 수로 끊고 `▶ 다음 조각 N` 을 알려준다. `size=100&page=0` 같은 쿼리 꼴이 섞이면 결과가 통째로 `[BLOCKED…]` 가 되므로 포매터가 `=` 를 전각 `＝` 로 바꿔 둔다. URL·19자리 id 는 그대로 통과한다(2026-09-29 실측 — 링크는 `fmtLinks` 가 주소 그대로). 포매터 첫 줄이 `ERR …` 면 결과가 아니라 오류다(로그인 → 탭 새로고침 → 재주입 1회).
5. **받기·쓰기 준비(기능 4~5 를 처음 쓸 때 한 번)**: `python scripts/dooray_io.py check` → `[요약] 인증 OK — 이름`. 토큰이 없거나 만료면 한 줄 안내가 나온다(값은 출력하지 않는다). `requests` 가 없으면 설치 명령을 알려 주고 사용자 확인 뒤 설치.

## 기능 1. 찾기 (대화형, 조회 전용 · confirm 불필요) — ★ 기본
"작년에 ○○ 과제 보고서 작성하던 업무 어디 있지", "4월 이후 ○○ 가 올린 에폭시화 발표 슬라이드 찾아줘", "견적서 첨부했던 업무".
1. **말 → 검색어 묶음** — 핵심어와 동의어·영문·약어·사람 이름을 **묶음**으로 만든다. 한 묶음 안 낱말은 AND, 묶음끼리는 합친다. 예: `[['○○사업'], ['영문 사업명'], ['○○사업','보고서']]`. 드라이브를 위해 파일 이름에 들어갈 말(발표자 이름·`yymmdd`·"발표")을 묶음으로 더한다. 기간은 `since`·`until`('YYYY-MM-DD', 한국시간, **수정일** 기준). 애매하면 **한 번만** 되묻고 시작.
2. **한 번에 검색** — `window.__d=null; kkDooray.find([['…'],['…','…']], {since:'2026-04-01'}).then(r=>window.__d=r, e=>window.__d={error:String(e)}); 'started'` → `kkDooray.fmtFind(window.__d)`.
   - 옵션: `tasks:false`·`drive:false`(한쪽만), `detail:5`(본문·첨부·댓글까지 읽어 둘 위쪽 업무 수), `paths:10`(폴더 경로를 붙일 드라이브 항목 수), `comments:10`, `kind:'file'|'folder'`, `ext:'pptx|hwp'`, `projectId`, `maxPages:3`(묶음당 100건씩).
   - 머리줄 `⚠ 잘림` = 상한에서 멈춤 → 낱말을 더해 좁히거나 `maxPages` 를 늘린다. `⚠ 업무:`·`⚠ 드라이브:` = 그쪽 검색 오류(**없음이 아니다**).
3. **더 보기** — `kkDooray.fmtTasks(window.__d.tasks, 6)` / `kkDooray.fmtDrive(window.__d.drive, 6)` (둘째 인자 = 시작 번호).
   업무 줄 `번호 | 수정일 | 상태 | 프로젝트 | 제목 | 작성자 | 첨부·댓글·하위` · 드라이브 줄 `번호 | 수정일 | 종류 | 드라이브 경로 | 이름 | 크기 | 올린 사람`.
4. **뜻으로 고르기** — 제목·본문·댓글·첨부 이름·경로를 읽고 질문에 맞는 것만 남긴다(검색어는 거르기용일 뿐). 업무 본문 `kkDooray.fmtTask(window.__d.tasks.items[N])`(이어 읽기는 셋째 인자 offset), 댓글 `fmtComments(…)`, 첨부 `fmtFiles(…)`. `find` 가 위 5건은 이미 읽어 두었다 — 다른 건은 `kkDooray.getTasks([window.__d.tasks.items[7], window.__d.tasks.items[9]]).then(()=>window.__g='done', e=>window.__g=String(e)); 'started'` 뒤 같은 포매터로(목록 항목에 그대로 채워진다).
5. **결과 제시** — 물어본 것부터: 찾은 것을 사건·주제별로 묶어 표로(업무: 날짜·프로젝트·제목·작성자·상태·첨부 / 드라이브: 날짜·드라이브·경로·이름·올린 사람), 건마다 **링크**. 링크는 `kkDooray.fmtLinks(window.__d.tasks)` / `fmtLinks(window.__d.drive)`(번호 = 목록 번호, 항목 1건도 된다)의 주소를 그대로 쓴다.
   - 업무 `https://kist.gov-dooray.com/task/{프로젝트}/{업무}` · 드라이브 `https://kist.gov-dooray.com/drive/{프로젝트}/views/{파일}`(드라이브에서 그 파일이 선택되고 오른쪽에 경로·미리보기가 뜬다).
   - 주소가 가려져 보이면 `fmtLinks(x, 0, 12, {hy:true})` 의 하이픈 번호에서 `-` 를 지워 위 형식으로 조합.
   - 무엇을 제외했는지 한 줄 덧붙인다.
6. **후속 질문은 들고 있는 결과로** — "그중 hwp 만" → `kkDooray.fmtDrive(kkDooray.only(window.__d.drive, {ext:'hwp'}))`, "○○ 가 올린 것만" → `only(…, {who:'○○'})`, "댓글에 ○○ 나온 업무" → `only(window.__d.tasks, {text:'○○'})`(본문·댓글을 읽어 둔 건만 대상), 기간 → `{since, until}`, 종류 → `{kind:'folder'}`. 새 낱말이 필요할 때만 다시 `find`.

## 기능 2. 자세히 (조회 전용)
- **업무**: `getTask(항목, {comments:20})` 또는 `getTasks([항목…])` → 항목의 `.detail` = 본문(마크다운·HTML 을 글로), 첨부 목록(이름·크기·올린 사람, 댓글에 단 파일은 한 번만 '댓글 날짜'로), 댓글(최신순). 댓글이 더 필요하면 `{comments:100}`. 하위 업무 수는 목록 줄의 `하위N`.
- **드라이브**: `window.__p=null; kkDooray.drivePaths(window.__d.drive, 30).then(r=>window.__p=r, e=>window.__p=String(e)); 'started'` 로 경로를 더 채운다(`find` 는 위 10건만). 폴더 안 전체 목록은 `python scripts/dooray_io.py drive-ls <폴더 링크>`(토큰) 또는 링크로 열어 보게 한다.

## 기능 3. 파일 내용 읽기 (⚠️ 파일마다 사용자 허락 후)
"그 슬라이드에 Cu 얘기가 있는지 봐줘", "첨부된 보고서 초안에 마감일이 뭐라고 돼 있어?"
1. **먼저 묻는다** — 파일 이름·크기·위치(드라이브 경로 또는 업무 첨부)를 보여주고 *"이 파일 내용을 읽어 볼까요? 파일은 저장하지 않고 브라우저 안에서만 읽습니다."* 허락한 파일만 읽는다.
2. 드라이브 항목: `window.__r=null; kkDooray.readFile(window.__d.drive.items[N]).then(r=>window.__r=r, e=>window.__r={error:String(e)}); 'started'` → `kkDooray.fmtText(window.__r, 800)`(이어 읽기는 셋째 인자 offset). 업무 첨부는 `kkDooray.filesOf(업무항목)[K]` 를 넘긴다(`fmtFiles` 번호).
3. **지원**: hwp(한글 5.0)·hwpx·docx·pptx(발표 순서, 발표자 메모는 `{notes:true}`)·xlsx(시트별 셀 값)·txt·md·csv·json·html. **미지원**: PDF·옛 형식(ppt·doc·xls)·그림·압축 → `읽기 미지원 …` 이 온다 — 링크로 열어 Dooray 미리보기로 보게 하거나, 사용자가 원하면 기능 4 로 내려받아 PC 에서 열게 한다. 30MB 넘으면 거부(사용자가 원하면 `{maxMB:N}`). 암호 걸린 hwp 는 못 읽고, 배포용 hwp 는 한글이 남긴 미리보기 글(앞부분)만.
4. 답에는 **필요한 부분만** 인용한다(파일 이름·슬라이드·쪽 표시). 읽은 내용을 파일로 남기거나 다른 곳에 보내지 않는다.

## 기능 4. 내려받기 — 업무 첨부·드라이브 파일 → PC (⚠️ 허락 후)
"그 업무 첨부 다 받아줘", "그 발표 파일 내려받아줘", "드라이브 ○○ 폴더의 결과정리 파일 받아줘".
1. **대상 정하기** — 찾은 결과의 링크를 그대로 쓴다: 업무 `fmtLinks(window.__d.tasks)` 의 주소 + 첨부 id `fmtFiles(업무항목, 0, 15, {ids:true})`, 드라이브 파일 `fmtLinks(window.__d.drive)` 의 `…/views/…` 주소. 사용자가 링크를 주면 그 링크.
2. **미리보기** — `python scripts/dooray_io.py task-download <업무 링크> --file <id>…`(또는 `--all`) / `drive-download <파일 링크>…` [`--to <폴더>`]. `--yes` 없이는 아무것도 받지 않고 **파일 이름·크기·저장될 경로**만 보여 준다. 저장 폴더 기본값은 Windows '다운로드' 폴더(`KIKI_DOWNLOADS` 로 바꿈), 사용자가 말한 폴더가 있으면 `--to`.
3. **묻는다** — 미리보기의 파일 이름·출처(업무 제목 또는 드라이브 경로)·크기·저장 위치를 보여 주고 *"이대로 내려받을까요?"* → 예면 같은 명령 끝에 `--yes`. 끝줄 `[요약] 받음 N / 실패 M → 폴더` 를 확인하고 저장 경로를 알려 준다.
4. 지키는 것(스크립트가 한다): 같은 이름이 있으면 ` (2)` 로 — **덮어쓰지 않는다** / 이름의 `\ / : * ? " < > |` 는 `_` / 받다 멈추면 `.part` 만 남고 원래 이름은 생기지 않는다 / 파일 대신 오류 응답이면 저장하지 않는다 / 폴더째 받기는 하지 않는다(파일을 골라서).
- **토큰이 없을 때만** 브라우저로 한 파일씩: 허락 후 `window.__v=null; kkDooray.saveFile(window.__d.drive.items[N]).then(r=>window.__v=r, e=>window.__v={error:String(e)}); 'started'` → `kkDooray.fmtSaved(window.__v)` → Chrome 다운로드 폴더. 업무 첨부는 `filesOf(업무항목)[K]`. 같은 탭에서 두 번째부터는 Chrome 이 막을 수 있다 → 주소창의 '여러 파일 다운로드' [허용]을 부탁하거나 토큰 경로를 권한다.

## 기능 5. 쓰기·올리기 — 업무 글·댓글·첨부, 드라이브 (⚠️ 매번 미리보기 → 사용자 확인 → `--yes`)
"그 업무에 '수정본 올렸습니다' 댓글 달아줘", "○○ 프로젝트에 '○○ 보고서 취합' 업무 올려줘(담당 ○○)", "이 파일 그 업무에 첨부해줘", "이 파일들 드라이브 ○○ 폴더에 올려줘".
- **글은 사용자가 준 그대로** 쓴다(임의 보강 금지). Claude 가 초안을 쓴 경우 초안 전체를 보여 주고 승인받은 뒤 쓴다. 긴 글·여러 줄은 UTF-8 임시 파일에 써서 `--text-file` 로(쓰고 나면 지운다).
- **댓글**: `python scripts/dooray_io.py task-comment <업무 링크> --text-file <파일>` → 미리보기(업무 번호·제목, 글자 수, 앞부분) → *"이 업무에 이 댓글을 달까요? 업무 담당·참조에게 알림이 갑니다."* → `--yes` → 링크.
- **업무 만들기**: `task-create --project <프로젝트 이름|링크> --subject "제목" --text-file <본문> [--to 이름…] [--cc 이름…] [--attach 파일…]` → 미리보기(프로젝트·제목·담당(기본 나)·참조·본문 앞부분·첨부) → 확인 → `--yes` → 새 업무 링크. 담당·참조는 **그 프로젝트 멤버만**. 이름이 여럿·멤버 아님·프로젝트 이름이 여럿이면 스크립트가 멈추고(종료 코드 2) 후보만 준다 → 사용자에게 골라 달라고 해서 다시(메일 주소로 구분). 마감일·하위 업무·상태 변경은 하지 않는다(Dooray 화면에서).
- **업무에 파일 첨부**: `task-attach <업무 링크> 파일…` → 미리보기 → 확인 → `--yes`.
- **드라이브 올리기**: 올릴 곳 = 찾은 폴더의 링크(`…/views/…` 폴더도 된다)·사용자가 준 폴더 링크·`private`(내 드라이브 최상위). 필요하면 `drive-ls <폴더>` 로 안을 보여 준다. `drive-upload <폴더> 파일…` → 미리보기(드라이브·경로·파일·크기) → 확인 → `--yes` → 올린 파일 링크. 폴더에 **같은 이름이 있으면 멈춘다**(코드 2) → *"같은 이름 파일이 있습니다 — 이름 뒤에 (2)를 붙여 따로 올릴까요, 새 버전으로 올릴까요?"* → `--as-copy` 또는 `--new-version`.
- 실행 뒤 끝줄 `[요약]` 을 확인하고 링크를 준다. 실패가 있으면 그 줄(`! …`)을 그대로 보고한다.

## 안전 규칙
- **찾기·자세히·내용 읽기(기능 1~3)는 조회 전용** — 브라우저 코어에는 쓰기 호출이 없다.
- **쓰기·올리기(기능 5)는 한 건 한 건 사용자 확인 후** — 미리보기로 **어디에(프로젝트·업무·폴더)·무엇을(제목·글·파일)·누구에게(담당·참조)** 를 보여 주고 "예"를 받은 뒤에만 `--yes`. 확인은 그 작업에만 유효하다(다음 작업은 다시 묻는다). 알림이 가는 작업(댓글·업무)은 그 사실을 함께 말한다.
- **내려받기(기능 4)는 파일 이름·출처·크기·저장 위치를 알리고 허락 후**. 덮어쓰지 않는다.
- **하지 않는 것**: 삭제·휴지통·이동·이름 바꾸기·업무 상태/담당 변경·권한·공유 설정. 요청이 오면 Dooray 화면에서 직접 하도록 안내한다.
- **토큰**: 값은 어디에도 출력하지 않는다(`check` 는 길이·출처만). 채팅 붙여넣기는 노출 위험을 항상 경고. 파일 호스트가 dooray 가 아니면 토큰을 보내지 않고 멈춘다(스크립트).
- 검색 결과·본문·파일 내용은 KIST 내부 자료 — 사용자에게 보여주는 용도로만 쓰고 외부로 보내지 않는다. 쓰던 Dooray 탭의 화면을 다른 곳으로 옮기지 않는다.

## 부트스트랩 (첫 사용 또는 "kk-dooray 설정")

> 🐱 **키키 인사(정체성)**: 첫 실행의 첫 줄은 *"안녕하세요 🐱 kk-dooray 를 준비할게요."* 한 줄, 그 다음부터는 평소 문체. 작업 보고의 첫 줄은 상황별 머리표: `😸 완료 — kk-dooray`(정상) / `😻 완료`(확인할 것 없음) / `😼 완료`(사용자가 할 일 남음: 결재 상신·확인) / `😺 완료`(조회만 한 가벼운 작업) / `🙀 중단`(막혀서 멈춤, 상황 보고) / `😿 부분 완료`(일부만 처리). 제출 문서·적요·파일명·오류 문구에는 넣지 않는다.

1. 실행 준비 1~2 (로그인·주입 확인). 찾기·읽기는 설정 파일·토큰·설치할 것이 없다고 알린다.
2. `python scripts/dooray_io.py check` 를 조용히 한 번 — 토큰이 있으면 "받기·쓰기·올리기도 바로 됩니다", 없으면 "받기·쓰기·올리기를 쓰실 때 토큰을 만들면 됩니다(그때 안내)" 한 줄. 여기서 발급을 재촉하지 않는다.
3. **기능 안내(반드시 출력 — 첫 실행은 여기서 끝)** — 예시로 보여준다:
   - *"작년에 ○○ 과제 보고서 작성하던 업무 어디 있지"* / *"4월 이후 ○○ 가 올린 발표 슬라이드 찾아줘"*
   - *"그중 hwp 만"* → *"그 파일에 ○○ 얘기 있는지 봐줘"* → *"그 파일 내려받아줘"*
   - *"그 업무에 '확인했습니다' 댓글 달아줘"* / *"이 파일 드라이브 ○○ 폴더에 올려줘"*
   - 한 줄씩 덧붙인다: 드라이브는 파일 속 글이 아니라 **이름·올린 사람**으로 찾는다 / 파일 내용은 **파일마다 허락받고** 읽는다 / 받기·쓰기·올리기는 **미리보기를 보여 드리고 확인받은 뒤**에만 한다.
