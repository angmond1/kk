# kk-wiki — KIST Wiki 2.0 규정·지침 찾기

> 🐱 **부르는 말**: "키키야 …"·"김키키 …"·"김키키씨 …" 로 시작하는 요청도 이 skill 로 처리한다. 문장 맨 앞의 부르는 말은 요청에서 빼고 읽는다 — 사람 이름·검색어·발신자로 쓰지 않는다(문장 중간 '김키키와·김키키가'처럼 요청의 대상인 이름은 사람). 이 skill 일이 아니면 [`../_shared/kiki_call.md`](../_shared/kiki_call.md) 표에서 맞는 kk skill 로 넘긴다.

## 핵심 한 줄
**1 규정 찾기(자연어 → 관련 조항 전부 + 링크 + 최신 확인 + 담당자)** · **2 스냅샷 만들기·갱신**(전체 본문 로컬 저장 + **첨부 문서를 절 단위 글로 풀어 같이 검색**) · **3 담당자표 갱신**(포탈 게시판 "부서별업무분장표" 부서별 최신 글) · **4 포탈 공지 캡처**(위키보다 먼저 뜨는 개정 안내를 날짜 붙여 현행 계층에). 조회 전용 — 위키·게시판에 쓰는 일은 없다.

## 진행 표시 이모지 (매 작업 · 사용자 요청 2026-09-30)
사용자가 흐름을 한눈에 보도록 **아래 순간에는 그 응답의 첫 줄을 이모지 머리표로 시작한다**(머리표 + 한 줄 요약, 표·설명은 그 아래). 첫 실행 때만이 아니라 **질문마다** 붙인다(한 번도 안 나오면 안 된다). 이모지는 **대화창에만** — 저장 파일(ocr/·staff/ 덤프), 스크립트 인자, 오류 원문에는 넣지 않는다.

| 순간 | 첫 줄 | 예 |
|---|---|---|
| ① 질문 파악 — 검색 전에 무엇을 찾을지 한 줄로 보여 줄 때 | `🐱 파악했어요 — …` | `🐱 파악했어요 — 해외출장 + 휴가 연계 · 신청 방법·서류·비용 부담` |
| ② 답을 보여 줄 때(기능 1 답 제시) | `😺 답 — …`(규정·절차) / `📞 담당자 — …`(누구에게 연락할지 묻는 질문) / `😼 답 — …`(상충·최신 확인 실패처럼 사용자가 확인할 것이 남을 때) | `😺 답 — 해외출장 휴가 연계: 가능, 인정기간 밖은 휴가원` · `📞 담당자 — 시설운영팀 전기실 (SOS 신청)` |
| ③ 갱신 작업이 끝났을 때(결과 확인까지 마친 뒤) | 상황별 고양이 머리표 | `😸 완료 — 스냅샷 갱신 NNN쪽 (신규 N · 변경 N)` · `😻 완료 — 담당자표 변경 없음` · `😿 부분 완료 — N팀 중 M팀` |
| ✖ 중간에 오류·실패 | `⚠️ 오류 — 무엇이 · 왜 → 다음에 할 것` / 막혀서 멈추면 `🙀 중단 — 원인` | `⚠️ 오류 — 최신 확인 실패(토큰 만료) → 브라우저로 다시 확인할게요` · `⚠️ 검색 0건 — 동의어를 넓혀 한 번 더` |

- **이모지는 딱 이 자리에만**(사용자 확정 2026-09-30 "너무 많이 쓰지 말고"): 위 첫 줄 머리표 + 답 안 절 제목 두 개 — `📞 담당자` 절, `⚠️ 페이지 간 상충` 절. 본답·부가사항·위키에 없는 것·출처 절 제목, 표 안, 문장 중간에는 넣지 않는다.
- `📞` = 담당자·연락처, `⚠️` = 오류·실패·경고(멈추지 않는 경고 줄도 `⚠️ 최신 확인 실패 — 이 쪽은 스냅샷 기준(YYYY-MM-DD)` · `⚠️ 담당자표 오래됨 — 게시판 최신 글 YYYY-MM` 처럼 앞에). 그 밖의 머리표는 고양이 얼굴: `😸 완료`(정상) / `😻 완료`(확인할 것 없음) / `😼`(사용자가 할 일·확인할 것 남음) / `😿 부분 완료` / `🙀 중단`.
- 한 응답에 머리표는 첫 줄 하나. 매 줄마다 이모지를 달지 않는다.

## 왜 스냅샷인가
위키 검색창은 키워드 한 번에 한 페이지씩 보여준다. 규정 질문은 "관련 조항을 빠짐없이"가 핵심이라 본문 373페이지(≈3MB)를 로컬에 두고 Claude 가 넓게 훑어 뜻으로 고른다. 최신성은 **인용할 페이지의 수정일을 API 로 대조**해 지키고, 바뀐 페이지만 다시 받는다.

## 왜 첨부까지, 그리고 계층 (2026-09-30)
위키 75쪽은 "첨부 파일을 확인하세요"로 끝나고 규정 원문(고시·비목표·전결표·길라잡이·행정원 지침서)은 첨부 212건에만 있다. 그래서 첨부를 받아 절 단위 글(`attachments_text/`)로 풀어 같이 검색한다. 다만 **위키 본문·포탈 공지가 PDF 보다 최신인 경우가 많다**(예: 회의비 1인 한도 3만→5만원, 정산과제 외부인 = 타 기관 소속 → 과제 미참여자(KIST 소속이어도), 사전 내부결재 폐지 2026-08-01). 그래서 출처를 세 계층으로 나누고 답의 첫 표는 항상 계층 1 값으로 쓴다:

| 계층 | 출처 | 답에서 |
|---|---|---|
| **1 현행** | 위키 본문 `pages/`(인용 때 fresh 확인) · 이미지 판독본 `ocr/` · 포탈 공지 캡처 `notices/` | 첫 표의 값. 꼬리표 `[위키 2026-09-15]` `[포탈공지 2026-08-01]` |
| **2 첨부** | 위키 첨부 문서의 절(고시·비목표·집행기준·길라잡이 5~7장 …) | 본문에 없을 때 인용. `[첨부 2024-09 길라잡이 p.148]` |
| **3 구버전** | 새 판이 있거나(`← 대체`) 기준일 3년 초과 문서의 절(행정원 지침서 2021, 정부수탁 안내서 2022, 종합생활안내 2019, 길라잡이 1~4장) | 단독 근거 금지. `[구버전 2021-12 행정원 p.122]` + 현행 값 앞세움 |

낡은 값의 대응표는 [`../_shared/rule_changes.md`](../_shared/rule_changes.md)(kk-pay·kk-meet 공용) — 추출 때 옛 값이 든 절에 `⚠ 구값` 이 붙고, 답에서는 `현행 5만원 (구버전 2021: 3만원)` 처럼 현행을 앞에 쓴다. 문서의 성격도 다르다: **규칙(what)은 위키·길라잡이·안내서, 화면 절차(how)는 행정원 지침서** — 한 답에 둘을 섞되 꼬리표로 구분한다.

## 전제 (환경)
- 공통 환경 점검은 [`../_shared/environment_setup.md`](../_shared/environment_setup.md) 0단계. Python 3 필요(`requests` 는 토큰 경로에서만, 실행 직전 설치).
- **인증 두 경로 — 같은 결과**:
  - **A. Dooray 토큰(권장)**: `<kiki_root>/token.txt`(kk-pay 와 공유). Python 하나로 수집·증분 갱신·최신 확인·첨부 다운로드까지. 브라우저 불요, 출력 제한 없음.
  - **B. 토큰 없음**: 평소 쓰는 Chrome(Claude in Chrome) 의 Dooray 로그인 세션으로 코어(`scripts/kk_wiki_ops.js`)를 주입해 수집 → export JSON 다운로드 → `wiki_snapshot.py import`. 최신 확인도 코어 `checkFresh`. 첨부는 못 받는다.
- 스냅샷 위치 `{kiki_root}\wiki\`(기본 `C:\kiki\wiki` / `~/kiki/wiki`): `pages/<경로>.md`(frontmatter + 본문), `index.json`, `index.md`(목록), `raw/`, `CHANGES_yymmdd.md`, `ocr/`(이미지 표 판독본), `notices/`(포탈 공지 캡처), `attachments/`(첨부 원본, 토큰) → `attachments_text/<pageId>/<파일>/NN_<절>.md`(절 단위 글) + `attachments_index.json/.md`(절 목록·실패 목록), `docs/`(위키에 없는 외부 문서 PDF), `docs_manifest.json`(선별 규칙 덮어쓰기, 기본은 skill 의 `assets/docs_manifest.json`).
- ⛔ **위키 내용은 KIST 내부 자료** — 스냅샷·첨부·검색 결과를 repo·공개 저장소·채팅 외부로 옮기지 않는다. skill 에는 수집 방법만 있고 내용은 0.

## 기능 (4가지)

### 1. 규정 찾기 (자연어 → 관련 조항 전부, 조회 전용 · confirm 불필요)
"출장 갈 때 식비 한도가 어떻게 돼?", "법인카드로 회의비 쓸 때 사전결재가 아직 필요해?", "외자 구매 절차와 필요한 서류 다 알려줘".

**⚡ 빠른 길 (기본 — 도구 호출 1번, 2026-09-30 사용자 지적 "간단한 답인데 너무 오래 걸린다")**: 느린 원인은 스크립트(검색 0.7초·최신 확인 1초)가 아니라 검색 → 본문 Read → fresh → 담당자를 **따로 부르던 왕복 4번**이었다. 그래서 먼저 **한 번만**:
`python scripts/wiki_ask.py <검색어…> --staff <담당 업무 낱말>` (예: `wiki_ask.py 숙박비 "국외|해외" "등급|급지|리버모어" --staff 출장`)
→ 1.5초에 ① 후보 목록(계층·기준일·링크) ② 상위 문서마다 **검색어가 든 절만**(목차 덩어리 제외. 길면 줄 경계에서 줄이고, 표는 행을 자르지 않되 긴 표는 머리 행 + 검색어 든 행만 남기고 `(표 N행 중 M행만)` 을 적는다 — 나머지 행이 필요하면 그 문서를 Read) ③ 최신 확인 SAME/CHANGED(병렬, 토큰 경로) ④ 담당자 줄이 한꺼번에 나온다(6~8천 자). **이 출력만으로 답을 쓴다** — 아래 2~4단계를 따로 하지 않는다. 현행 결과가 2건 미만이면 스스로 첨부·구버전까지 넓힌다. 규정 원문이 첨부에만 있을 법하면 `--scope all`, 발췌가 모자라면 `--chars 12000` 이나 `--pages 5` 로 **한 번 더**(그래도 모자라면 그때 아래 단계). CHANGED 가 나오면 `wiki_snapshot.py fresh <id> --update` 후 다시 한 번. **토큰이 없으면** ③ 자리에 붙여 넣을 브라우저 호출이 나온다(`window.kkWiki.checkFresh({'<id>': <로컬 version>, …})…` — 로컬 version 까지 채워져 있음) → Dooray 탭에 `kk_wiki_ops.min.js` 를 주입한 뒤 그 줄을 그대로 실행하고 2~3초 뒤 `window.kkWiki.fmtFresh()` 로 SAME/CHANGED 를 읽는다(아래 4단계와 같은 2-스텝). CHANGED 면 토큰 없이 다시 받을 수 없으니 링크를 주고 바뀐 조항은 사용자가 원문 확인. 검색어는 처음부터 동의어를 `|` 로 넉넉히(한 번에 끝내는 게 목표).
아래 1~4 는 빠른 길로 부족할 때의 자세한 절차다.
1. **질문 분해** — 주제어와 **동의어·약어·행정 용어**를 넓게 잡는다(예: 회의비 → 회의비|식대|다과|간담회, 출장 → 출장|여비|일비|숙박). 대상 본부·팀이 짐작되면 경로 힌트(재무팀·인사경영팀·구매·자산팀·정보경영실 …)도.
2. **후보 수집** — `python scripts/wiki_search.py "회의비|식대" 한도 --top 30` 처럼 AND/OR 로 2~3번 돌려 후보를 넓게 뽑는다. 결과의 `pages/…` 경로와 발췌, 첨부 유무를 본다. 필요하면 `--list 재무팀` 으로 그 팀 페이지 목록을 통째로 훑는다(목록은 `index.md`).
   - **범위(2026-09-30)**: 기본은 **현행만**(`--scope current` = 위키 본문·판독본·공지) — 속도는 그대로. 결과가 3건 미만이면 스크립트가 `▶ 첨부·구버전 절에 N건 더 있음` 힌트를 내니 그때 `--scope all`(현행+첨부) 로 한 번 더. 규정 원문이 첨부에만 있는 질문(비목별 집행 기준·고시, 부처별 특이사항, 여비표, 청탁금지법 합산, 전결표)은 처음부터 `--scope all`. **화면 절차 질문**("통합정보에서 어떻게 신청해", "행정원이 뭘 확인해")은 `--scope all --kind procedure`(행정원 지침서 2021 이 주 출처). `--tier 2` 면 구버전 제외.

2. 이 게시판 화면은 그룹웨어 `ngw.kist.re.kr` 페이지가 iframe 으로 들어온 것이라 포탈 탭에서는 JS 로 접근이 막힌다. 그 iframe 의 주소(`…/xclick_kist/dispatcherKMS.jsp?…` 또는 `XClickController?isDispath=true`)로 **탭을 직접 띄운 뒤** 코어 `kk_wiki_ops.js` 를 주입한다. 목록은 코어가 직접 POST 하므로 **왼쪽 메뉴를 열 필요가 없다**(`XClickController?isDispath=true` 는 빈 화면이지만 같은 origin 이라 충분). 목록이 비어 오류가 나면 이 Chrome 에서 포탈 로그인이 안 된 것 → 로그인 후 다시.
3. `window.kkWiki.staffCollect()` → `staffStatus()` 로 진행 확인(목록 2페이지 + 글 20건 ≈ 50초). ⭐ **차분 갱신(평소 — 업무분장은 수시로 바뀐다)**: `python scripts/wiki_staff.py known` 이 찍는 `{팀:글번호}` JSON 을 `window.kkWiki.staffChanged(<JSON>)` 에 넣고 2~3초 뒤 `staffChangedStatus()` → 바뀐 팀만 `staffCollect({ list: window.kkWiki.changed })` → 아래 4 를 `--keep` 로. "변경 없음" 이면 그대로 끝. **기간 정책(사용자 2026-09-25)**: 2025-01-01 이후 글을 우선하고, 그 이후 글이 없는 존속 부서(시설운영팀·데이터정보팀 등)는 그 전 최신 글을 쓰되 **오래됨** 표시(`staffList({minDate, floorDate})`, 2020년 이전 글뿐인 부서는 개편 전 조직으로 보고 `excluded` 에만). 글은 'URL복사' 공유 주소를 숨은 iframe 으로 열어 읽으므로 **탭을 앞에 둘 것**.
4. `window.kkWiki.staffDownload()` — 덤프가 다운로드 폴더에 `kiki_staff_dump_yymmdd_<run>.txt` 로 저장된다(LLM 이 읽고 다시 적지 않는다) → 반환 문자열 끝의 명령 그대로 `python scripts/wiki_staff.py import --from-downloads --expect <run> [--keep] [보정덤프.txt …]`(그 run 의 덤프만 `{kiki_root}\wiki\staff\` 로 복사해 가져온다; 다운로드 폴더가 다르면 환경변수 `KIKI_DOWNLOADS`). **가져오기 보호(2026-09-27, 담당자표는 중대 자산)**: 수집 오류·표 인식 실패로 표가 빈 팀은 기존 표를 유지하고, 같은 글번호의 이미지 게시글은 기존 판독본(OCR)을 유지하며, `--keep` 없이 기존 팀이 빠지거나 덤프가 잘려 보이면(머리줄 팀 수 ≠ 읽은 팀 수, 끝 표시 없음) **저장하지 않는다** — 일부만 다시 받았으면 `--keep`, 조직 개편으로 정말 없어진 팀이면 `--force`. 저장 전 이전본은 `staff/_history/` 로. 다운로드가 막힌 환경에서만 옛 방식: **사용자에게 알린 뒤** `staffRender()` → `get_page_text` → `staff_dump_yymmdd.txt` 저장 → `import <그 파일>`(여러 파일은 뒤 파일이 같은 팀을 덮어씀. `--since 2025-01-01` 기본 — 그 이후 글이 없는 팀은 ⚠오래됨 표시. `--keep` 이면 기존 `staff.json` 의 팀을 유지한 채 새 덤프의 팀만 덮어씀 = 차분 갱신) → `staff.json`·`staff.md`. 끝나면 탭을 새로고침해 그룹웨어 화면을 되돌린다.
5. 확인: `python scripts/wiki_staff.py status` / `find 출장` / `team 재무팀`. `status` 의 "이미지·본문만 N" 이 0 이 아니면 6 으로(표가 있는데 "본문 없음"이면 헤더 규칙 문제 — 그 글을 직접 열어 확인, `references/staff_board.md` 표 절).
6. **이미지 게시글 판독(OCR)**: 덤프에 `(표 없음 — 이미지 게시글…)` 인 팀(2026-09-25 기준 가치혁신·총무복지·국제협력팀)은 그 글의 공유 주소(덤프의 url)를 탭에 열고 코어 주입 → `window.kkWiki.staffShowImage()`(본문 이미지 하나를 원본 폭으로 펼침) → `computer` `screenshot` 으로 전체를 본 뒤 `zoom` 으로 세로 400px 안팎 띠씩 잘라 읽어 행을 옮겨 적는다 → `staff_dump_yymmdd_ocr.txt`(같은 덤프 형식: `## 팀:` 줄은 원본 덤프 것 그대로, 헤더 행 포함, 병합 셀은 행마다 채움, 끝에 "(※ 이미지 게시글을 화면 확대 캡처로 판독해 옮김 — 날짜)") → `import <원본> <_ocr.txt>` → `team <팀>` 으로 행 수·이름을 캡처와 대조. 캡처가 30초 타임아웃이면 띠를 좁히거나 다시(전체 screenshot 이 또렷하면 그것으로). 절차 상세 `references/staff_board.md`.
- 담당자표는 **이름·내선이 든 내부 자료** — `{kiki_root}\wiki\staff\` 밖으로 내보내지 않는다. 반년 또는 조직개편 때 갱신.

### 4. 포탈 공지 캡처 (위키보다 먼저 뜨는 개정 안내 → `{kiki_root}\wiki\notices\`)
규정 개정은 위키 페이지가 고쳐지기 전에 **포탈 팝업·공지·통합정보 화면 안내**로 먼저 나온다(예: 통합정보 회의비 화면의 식비안내 팝업 = 2026-08-01 사전결재 폐지·과제 미참여자 참석 필수 — kk-meet 가 읽는다). 사용자가 "이 공지 저장해 둬" 하거나, 답하다가 위키와 다른 최신 안내를 보면:
1. 그 문구를 **그대로**(요약·보강 없이) `notices/yymmdd_<주제>.md` 로 저장 — frontmatter `title / kind: notice / source: 포탈 공지|통합정보 팝업|공문 / source_url / dated: 공지 날짜 / captured: 저장일 / note`. 본문은 원문 + 어느 화면·어느 경로에서 봤는지 한 줄.
2. `wiki_search.py` 가 `notices/` 를 **계층 1** 로 같이 검색한다(꼬리표 `[1·포탈 공지·날짜]`). 답에서는 위키 본문과 같은 급으로 쓰되 출처를 `[포탈공지 2026-08-01]` 로.
3. 값이 바뀐 개정이면 `../_shared/rule_changes.md` 에 한 행 더한다(사용자 확인 후) → 구버전 절의 `⚠ 구값` 표시가 따라온다.
- 포탈 로그인 세션·개인 알림(결재·급여)은 캡처하지 않는다. 공지 원문에 실명·내선이 있으면 그대로 두되 `notices/` 밖으로 내보내지 않는다.
- ⭐ **결재선(전결권자) 질문의 1차 출처 = 포탈 「행정 전결 사항 테이블」** `http://n.kist.re.kr:8088/ext/mobile/decision/decision.jsp`(로그인한 Chrome 에서만 열림, 스크립트로는 못 받음; 사용자 지정 2026-09-30). 구매요구서·출장·휴가·전문가 활용·자산 불용·물품반출·교육훈련·학연 등 **상황별 결재선이 한 페이지에** 있고, 위키 본문에는 구매요구서 금액별 전결이 없다. 캡처본 `notices/150325_행정전결사항_테이블.md`(표 머리 2015-03-25 이지만 **현행 기준으로 쓴다** — 구버전 꼬리표 금지). **원문의 '담당자' 칸(이름·내선)은 옛 정보라 옮기지 않았고 인용하지 않는다** — 담당자는 담당자표(`wiki_staff.py find`)로. 갱신: 그 주소를 Chrome 에 열고 `get_page_text` → 표를 다시 옮겨 적는다(담당자 칸 제외).
  - 자주 묻는 **구매요구서 결재선**(VAT 포함): 자본적 지출(연구장비) 2천만원 이하 연구책임자 · 5천만원 이하 센터장 · 1억원 이하 소장/본부장 · 2억원 이하 부원장 · 2억원 초과 원장 / 수익적 지출(재료) 1천만원 이하 센터장 · 3천만원 이하 소장/본부장 · 1억원 이하 부원장 · 초과 원장. 외자는 원화 환산. 장비심의요청서: 기관고유 3천만원 이상·정부부처 과제 1억원 이상. 이해관계업체 추천·사후처리는 전결 1단계 상향(구매자산팀 FAQ).

## 결과 점검 (스크립트·코어 결과를 쓰기 전)
공통 3줄은 `../_shared/environment_setup.md` '결과 점검' 절(요약 줄만 대조 → 어긋나면 원인 고쳐 1회 재실행 → 그래도 안 되면 수동 경로 + 사용자에게 알림). 이 skill 의 기대치:
- 스냅샷: `status` 쪽수가 직전(≈377)과 비슷해야 한다. 크게 줄었으면 쓰지 말고 `raw/_old_*` 보관분·백업 zip 을 확인. 검색 `N건` 이 0이면 동의어를 넓혀 **한 번** 더.
- 담당자표: import 요약 줄 `이전 N팀 → M팀, 새 글 k(, 이전 표 유지 j, 판독본 유지 i)` 을 본다. `⚠ 읽기 실패로 이전 표를 유지한 팀` 이 있으면 그 팀만 탭을 앞에 두고 다시 수집, `⚠ 새 이미지 게시글 — 판독(OCR) 필요` 면 기능 3-6. `저장하지 않았습니다 —` 는 보호 장치가 막은 것이니 이유대로(`--keep`/다시 받기) — `--force` 는 사용자에게 이유를 말하고 확인받은 뒤에만. `find` 결과가 0건이면 다른 단어로 한 번 더.
- `staffStatus()` 는 `teams N, tables T, image I, 표 인식 실패 U, errors E` — errors·표 인식 실패가 0 이 아니면 가져와도 그 팀은 이전 표가 유지된다(요약 줄에 나온다). `staffChangedStatus()` 가 `ERR` 를 담으면 그 원인부터(세션·팝업).
- 최신 확인: `fmtFresh()` 머리줄 `CHANGED k` 가 0 이 아니면 그 페이지를 다시 받아 읽고 인용한다. `ERR` 줄이 있으면 그 페이지는 확인 못 한 것 — 답에 "최신 확인 실패" 를 적는다.
- 첨부 추출: `wiki_extract.py status` 의 `파일 N, 절 M` 과 상태 집계를 본다(2026-09-30 기준 파일 210, 절 ≈1,400, `error` 는 양식 hwp 2·xls 1 뿐). `error` 가 늘면 그 파일만 `show <이름>` 으로 보고, 규정 원문이면 사용자에게 링크로 열어 보게 한다. 검색 결과에서 `← 대체` 가 붙은 절을 인용하지 않았는지, 첫 표의 값이 계층 1 인지 답을 보내기 전에 한 번 본다.

## 안전 규칙
- **조회 전용** — 위키 페이지 생성·수정·삭제 API 는 부르지 않는다.
- **내부 자료 격리** — 스냅샷·첨부·검색 결과는 `{kiki_root}\wiki\` 밖으로 내보내지 않는다. repo 커밋 금지(설치 폴더가 repo 이면 `{kiki_root}/wiki/` 는 `.gitignore` 의 `/wiki/` 로 제외되지만, 그래도 repo 안에 두지 않는 편이 안전).
- **원문 우선** — 규정은 요약하지 말고 조항을 인용하고 출처·수정일을 붙인다. 위키에 없는 내용을 지어내지 않는다.
- 토큰 값·세션 정보는 출력하지 않는다(파일에서만 읽는다).

## 부트스트랩 (첫 사용 또는 "kk-wiki 설정")

> 🐱 **키키 인사(정체성)**: 첫 실행의 첫 줄은 *"안녕하세요 🐱 kk-wiki 를 준비할게요."* 한 줄, 그 다음부터는 평소 문체. 작업 중·끝의 머리표는 위 **"진행 표시 이모지"** 표를 따른다(질문 파악·답·갱신 완료·오류마다). 저장 파일·스크립트 인자·오류 원문에는 넣지 않는다.

1. 환경 점검(위) → 토큰 유무 확인(있으면 A, 없으면 B 안내. 토큰이 없어도 되고, 있으면 첨부까지 받을 수 있다고 알린다).
2. `status` 로 스냅샷 확인 → 없으면 "위키 전체 본문을 내 PC 의 `{kiki_root}\wiki\` 에 저장합니다(≈3MB, 2~3분). 진행할까요?" → 예면 기능 2 로 수집. 토큰이 있으면 이어서 "첨부 문서(고시·길라잡이·지침서 등 212건, ≈365MB)도 받아 글로 풀어 두면 규정 원문까지 검색됩니다(5분쯤). 할까요?" 를 한 번만 — 아니요면 나중에 필요할 때 `attach` + `run`.
3. **기능 안내(반드시 출력)** — 예시: *"출장 식비 한도 알려줘"*, *"법인카드 회의비에 사전결재가 필요한지 규정 찾아줘"*, *"외자 구매 절차 관련 페이지 다 모아줘"*. 답은 원문 인용 + 링크 + 수정일로 오고, 인용 페이지는 매번 최신 확인된다고 안내. 첨부(hwp/pdf 원문) 다운로드는 토큰이 있을 때만.
4. 설정 파일 `~/.claude/kiki/kk-wiki.config.json` 은 기본값으로 충분하면 만들지 않는다(`kk-wiki.config.example.json` 참고).
