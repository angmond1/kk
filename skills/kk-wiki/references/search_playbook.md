# 규정 찾기 플레이북 — kk-wiki

## 흐름
1. **질문 → 검색어 묶음**: 주제어 + 동의어·약어·행정 용어 + (짐작되는 담당팀). 한 번에 못 맞추므로 2~3회 검색한다.
2. **후보 넓게**: `wiki_search.py A|B C --top 30` (AND 는 인자, OR 는 `|`). 0건이면 단어를 줄이거나 `--list <팀>` 으로 목록을 훑는다.
3. **본문 판독**: 후보 `.md` 를 Read. 조항을 **원문 그대로** 모으고, 표·번호 조항은 구조를 살린다.
4. **최신 확인**: 인용할 id 들을 `wiki_snapshot.py fresh … --update`(또는 `checkFresh`). 답에 수정일 표기.
5. **상충 대조**: 같은 수치·절차를 적은 페이지가 둘 이상이면 값과 수정일을 표로 나란히 놓고 비교한다(부서가 다르면 특히). 다르면 답에 "⚠️ 페이지 간 상충" 절.
6. **답**: 한눈에 표 → 구분별 → 상황별 처리 표 → 상충(있으면) → 없는 것/확인처 → 번호 출처. **첫 답은 요약**, 세부(원문·예외·절차)는 사용자가 더 물을 때 그 부분만.

## 흔한 함정
- **제목만 보고 판단**: 규정의 예외·단서는 본문 아래쪽이나 FAQ 페이지에 있다. FAQ(`FAQ/`, `■ 연구부문 FAQ/`)도 같이 검색.
- **개정 이력**: 같은 주제가 연도별 페이지로 여러 개면 `updatedAt` 최근 것을 우선하되, 옛 페이지에만 있는 조항은 "구 규정" 으로 표시.
- **첨부 전용 페이지**: 본문 0자 + 첨부만 있는 `(양식)…` 페이지는 첨부를 받아야 내용을 안다(토큰 경로 `attach`).
- **동명 기관·용어**: '계정' 은 과제 계정(예산)과 시스템 계정(로그인) 둘 다 → 경로로 구분.
- **없는 것을 채우지 말 것**: 위키에 없으면 없다고 하고 담당팀 확인을 권한다. 사용자 경험(kk-meet 등 다른 skill 의 규정 메모)은 참고로만, 출처는 위키로.
- **결재선·전결권자 질문**: 위키 본문에는 금액별 전결(특히 구매요구서)이 없다. 먼저 `notices/150325_행정전결사항_테이블.md`(포탈 행정 전결 사항 테이블, 사용자 지정 현행 기준)를 본다 — `wiki_ask.py "구매요구|출장|휴가|…" "전결|결재선|결재"`. 그 표의 담당자 이름은 옛 정보라 쓰지 않는다. 용역계약 전결표(구매·자산팀 5.용역계약)는 용역 전용이라 물품·장비에 쓰지 않는다.
- **회의비 사전결재·외부인**: 위키 첨부·옛 PDF(길라잡이·정부수탁 안내서·지침서·증빙 꿀팁 가이드)는 '사전 내부결재 필요'·'외부기관 참석자 필수'로 적혀 있다 → 현행은 2026-08-01 사용분부터 사전 내부결재 기본 폐지·과제 미참여자 참석 필수(재무팀 공지 2026-08-04, `../../_shared/rule_changes.md` meeting_preapproval·meeting_outsider). 구값 표시(⚠)가 붙은 절은 현행 값을 먼저 쓰고, 휴일·근무지 밖 사용의 차상위자 사전 내부결재는 현행이라는 점을 함께 적는다.
