# 메일 분류 정책 — 광고성/predatory 판별 패턴 (보편)

> 이 문서는 **누구에게나 오는** 광고성·predatory 메일의 **판별 패턴**만 담는다.
> 특정 사용자의 개인 발신처 목록·개인 분류 선호는 여기 두지 않는다(각자 `~/.claude/kiki/kk-mail.config.json`).

---

## 기능 4 — 스팸 신고 대상 (광고성/predatory) · 보편

아래 **강한 신호**가 겹치면 광고성 학회/저널 모객(predatory)으로 판단해 스팸 신고를 제안한다.

### 발신 도메인 신호
- **일회성·모객 전용 도메인**: `.info` / `.live` / `.top` 등 TLD에 컨퍼런스명만 박힌 주소, 또는 여러 분야 학회를 같은 패턴으로 대량 운영하는 모객 호스트.
- **대량발송 중계**: `@*.ccsend.com`(Constant Contact) 등 마케팅 메일 중계 경유. (전체 주소 단위 차단이라 무방)
- **정체불명 도메인**: 회사·학회 실체가 불분명한 신생/임의 도메인(`.cloud` 임의 호스트 등).
- **predatory journal 출판사**: 무차별 투고·special issue 권유로 알려진 출판사 계열.

### 본문·제목 신호
- 분야 무관 **무차별 "Invited Speaker / Invited Lecture / Keynote"** 초청.
- "주제·발표 형식 자유" (수신자 연구를 안 보고 보냈다는 신호).
- "special issue 기고 권유" + 마감 임박 압박 + **할인(%)** 미끼.
- 수신자 이름을 제목에 직접 박아 친밀감 위장("<이름> – Lead Global Discussions…").
- 명시적 학회 단체(ACS/RSC/KIChE/KSIEC 등) 부재, 운영사가 직접 모객.
- 제목을 거르는 조건으로 쓸 때는 저널·학회 **이름 구절만**(예: `Journal of ○○ Science`, `○○ Materials Science Conference`) — 광고 문구·인사말·번호는 메일마다 바뀐다(SKILL '제목 키워드 고르기').

### 피싱 (스팸 신고 + 사용자 경고)
- **계정·지갑·결제 '조치 필요'** 류 제목(예: `Action Required: Your ○○ Firmware Is Outdated`, 비밀번호 만료·계정 정지·결제 실패·보안 인증) + **그 서비스와 무관한 발신 도메인**.
- 사용자가 그 서비스를 쓰는지와 무관하게 링크를 누르지 않게 **표에서 따로 표시**하고, 스팸 신고와 함께 "링크를 누르지 마세요" 를 한 줄 덧붙인다. 본문 링크를 Claude 가 열지 않는다.
- (2026-09-27 실측: 받은편지함 3주치에서 지갑 펌웨어 피싱 1통 — 키워드 점수로는 0점이었다. 도메인·제목의 어긋남을 사람처럼 읽어야 잡힌다.)

### 기업 마케팅 (광고지만 predatory는 아님)
- 실제 업체의 webinar·신제품·세미나 홍보 뉴스레터. → **스팸 신고보다 "광고 폴더 분류(기능 2)"가 적절**할 수 있음(사용자 선택).

## 정상 메일 (≠ 광고) — 스팸/분류 대상 아님

- **학회 단체 공식 도메인**: `@acs.org`, `@rsc.org`, `@kiche.or.kr`, `@ksiec.or.kr`, `@kchem.org` 등.
- **본인 논문·심사 시스템**: editorialmanager / manuscriptcentral / scholarone / atypon 등에서 오는 **본인 투고·리뷰** 알림.
- **소속 기관 내부**: 본인 회사 도메인 행정·공지.
- **개인 1:1 메일**: 포닥 지원, 동료·교수의 직접 연락. → 스팸 신고 부적절(개인 발신).
- ⚠️ **개인(교수) 발신의 연사 섭외·공동연구 제안**: 답장·후속 대응 필요 → **폴더로 옮기지 말고 받은편지함 유지**.

## 기능 2 — 폴더 분류 (선택, 물어보고)

스팸까진 애매한 메일을 폴더로 분류할지 **사용자에게 먼저 묻는다**. 흔한 분류 축(예시일 뿐, 강제 아님):
- **광고**: 기업 마케팅·webinar·할인 홍보.
- **공고**: 연구재단/기관의 공식 공지·접수 안내.
- **학회**: 학회 사무국/단체 공식 발신(개인 교수 직접 메일 제외).
- **시약/거래처**: 시약·기자재 업체의 명세·안내.

> 어떤 축을 쓸지·폴더명·자동분류 여부는 **사용자 선택** → config에 저장.

### ⭐ 같은 도메인, 두 용도 분기 (NRF·KEIT·KIAT 패턴)

| 도메인 → **과제** | 정확주소 → **기관뉴스** |
|------|------|
| `nrf.re.kr` | `nzine@nrf.re.kr` |
| `keit.re.kr` | `email@keit.re.kr` · `nabis@keit.re.kr` |
| `kiat.or.kr` | `newsletters@kiat.or.kr` |

**Dooray는 `not_include`(제외)를 지원하지 않으므로**(검증 완료, -200200) 규칙 우선순위 `applyOrder`로 처리한다:
1. **정확주소(기관뉴스) 규칙을 먼저** — 낮은 `applyOrder`.
2. **도메인(과제) 규칙을 나중** — 높은 `applyOrder`.
→ `applyOrder` 순 적용으로 정확주소 메일이 기관뉴스에 먼저 잡힌다. (새로운 도메인·뉴스주소가 생기면 같은 표에 한 줄 추가.) ⚠️ "먼저 매칭 우선" 동작은 첫 적용 시 1건으로 확인 권장.

### 기존 분류와 충돌 시 (필수 — 사용자 지시)
사용자가 이미 비슷한 폴더·규칙을 가졌을 수 있다(예: 기존 "공고" 폴더에 과제+기관뉴스가 개별주소로 섞임).
→ 권장 분류 적용 **전에 현재 폴더·규칙을 조회**(`findAllFolders`+`listMailRules`)해서, 겹치면 **"기존 폴더에 합칠까요, 그대로 두고 새로 나눌까요?"**를 묻고 사용자 선택을 따른다. **임의로 기존 규칙을 덮어쓰지 않는다.**

## 기능 3 — 자연어 규칙으로 임의 분류

사용자가 "앞으로 X는 Y 폴더로"라고 하면 조건을 파싱해 규칙 생성:
- **기본 조건 = 발신 주소 1개**(`fromEmails`, 정확한 주소 `noreply@x.org`). 발신+제목+받는사람을 모두 맞추는 규칙은 제목이 조금만 바뀌어도 빠져나가므로 **기본으로 붙이지 않는다**(2026-09-24 사용자 확정).
- **제목 기준**(`subjectKeywords`, 발신과 AND)은 사용자가 명시했을 때, 또는 같은 주소에 성격이 다른 메일이 섞여 사용자가 세분화를 택했을 때만. confirm 때 "추가할 수 있다"고 한 줄 안내만. 넣을 때는 **제목 전체가 아니라 매번 그대로인 핵심 구절만**(예: `○○업체(유)로부터 전자세금계산서`, `거래명세서_○○업체`) — 번호·날짜·머리말·태그·인사말·광고 문구는 뺀다(SKILL '제목 키워드 고르기', 2026-09-27).
- 발신 **도메인** 단위(`nature.com`)는 그 도메인이 한 성격일 때만. 기관 도메인 전체는 아래 경고.
- 과거 메일 소급(`applyBefore`)은 사용자에게 확인.

### 주의
- **도메인 양면성**: 한 도메인이 정상+광고 섞이면 도메인 일괄 규칙 금지(건별).
- **기관 도메인 전체 규칙 경고**: 예) 연구재단 도메인 전체를 한 폴더로 보내면 중요 공문까지 휩쓸림 → 발신 주소 단위 권장.
